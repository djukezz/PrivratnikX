# API Привратника

Неофициальное описание бэкенда `privratnik.net`. Собрано из старого клиента PrivratnikSimpleA
и из официального приложения «ПривратникЪ» 2.9.2 (`ru.techmas.barrier`). Официальное приложение
написано на React Native; бандл Hermes декомпилирован с помощью `hermes-dec`.

Статусы в таблицах:

- **проверено** — работает в PrivratnikX или проверено запросом вживую (17.10.2026);
- **из клиента** — видно в коде официального приложения, вживую не проверялось.

## Адреса

| Назначение | Адрес |
|---|---|
| Основной API | `https://api.privratnik.net:44590/app/api.php` |
| Запасной API 1 | `https://apir1.privratnik.net:44590/app/api.php` |
| Запасной API 2 | `https://apir2.privratnik.net:44590/app/api.php` |
| Видеосервер (Flussonic) | `https://{domain}/…`, `domain` приходит в ответе на запрос камер, например `cam0.privratnik.net` |
| Архив DVR | `https://apir2.privratnik.net/dvr/ranges` — есть в клиенте, но сейчас отвечает 404 |
| Чат | `http://62.109.21.76:8127/api` + `/auth/token`, `/chat/messages`, `/chat/message`; WebSocket `ws://62.109.21.76:8127/` (из клиента) |
| Логи клиента | `https://logs.ruyou.ru` + `/site/log` (из клиента) |

Официальный клиент перебирает три API-адреса по очереди. Адрес, который ответил ошибкой или
статусом не 200, он исключает из списка (`tryDomainsAndRemoveBad`). PrivratnikX пока ходит
только на основной.

## Общий формат запросов

- Все запросы — `POST` на `api.php`, тело `multipart/form-data`.
- Какой это запрос, определяет набор полей формы. Отдельного поля «метод» нет: например,
  наличие поля `cam` означает запрос камер.
- После авторизации к каждому запросу добавляются два поля:
  - `login` — номер телефона в формате `7XXXXXXXXXX`, 11 цифр;
  - `key` — 32 hex-символа, получается по SMS (см. ниже).
- Ответ — JSON, HTTP-статус почти всегда 200, даже при ошибке.
- Неверная пара `login`/`key` даёт `{"login":"0"}` — по этому ответу ловится протухший или
  отозванный ключ (проверено).
- Есть и вариант `application/x-www-form-urlencoded` (`login=…&key=…`, функция `_xFormApi`
  в клиенте), но multipart работает для всего.

Пример на curl. В PowerShell пишите `curl.exe`, а не `curl`, и каждое поле `-F` берите целиком в кавычки:

```bash
curl -F "login=7XXXXXXXXXX" -F "key=<KEY>" -F "cam=" "https://api.privratnik.net:44590/app/api.php"
```

## Авторизация

### 1. Запросить SMS — проверено

| Поле | Значение |
|---|---|
| `number` | `7XXXXXXXXXX` |

Ответ: HTTP 200 при успехе. На телефон приходит 5-значный код.

### 2. Обменять код на ключ — проверено

| Поле | Значение |
|---|---|
| `number` | `7XXXXXXXXXX` |
| `smsCode` | 5 цифр из SMS |

Ответ:

```json
{"key": "0123456789abcdef0123456789abcdef"}
```

Сервер может прислать ключ с пробелами или переводом строки по краям — их нужно обрезать.
Ключ сохраняется в настройках и дальше отправляется в каждом запросе как `key`. Он не протухает:
ключ, полученный один раз, продолжает работать (проверено на практике). Отзывается ли старый ключ при новом
входе по SMS, не проверялось. По ключу можно открывать шлагбаумы и смотреть камеры, так что
храните его как пароль.

## Шлагбаумы

### Список — проверено

| Поле | Значение |
|---|---|
| `barrier` | `""`. Официальный клиент шлёт `timestamp` |
| `login`, `key` | см. выше |

Ответ — массив объектов (проверено):

```json
[{
  "id": "<barrier_id>",
  "bid": "<bid>",
  "coordinate_X": "55.…",
  "coordinate_Y": "37.…",
  "address": "ул. Примерная, д. 1",
  "number": "7XXXXXXXXXX",
  "number2": "7XXXXXXXXXX",
  "user_info": "Жилой дом",
  "old": null
}]
```

- `id` — тот самый `barrier_id`, который передаётся при открытии и приходит у камеры.
- `coordinate_X` — широта, `coordinate_Y` — долгота.
- `number`, `number2` — номера GSM-модуля шлагбаума, на них можно позвонить для открытия.
- При `barrier=timestamp` в конец массива добавляется служебный элемент `{"timestamp": <unix>}`,
  клиент его отфильтровывает.
- PrivratnikX читает только `id` и `address`.
- Поля `devId`, которое официальный клиент отправляет при открытии, в списке нет.

### Открыть — проверено

| Поле | Значение |
|---|---|
| `barrier_id` | id шлагбаума из списка |
| `command` | `open` |
| `bid`, `devId` | официальный клиент передаёт их из объекта шлагбаума; без них тоже работает |
| `login`, `key` | |

Ответ:

```json
{"state": 1}
```

`state == 1` — открыто, любое другое значение — ошибка. PrivratnikX ждёт ответа 5 секунд.

### Прочие операции — из клиента

| Операция | Поля |
|---|---|
| Открыть звонком с номера | `from`, `to` |
| Добавить шлагбаум | `addBarrier=""`, `tel_gsm`, `address`, `user_info` |
| Изменить | `UpBarrier=""`, `barrier_id`, `address`, `user_info`, `point_x`, `point_y`, `bid`, `devId` |
| Удалить координаты | `rmCoordinates=""`, `barrier_id`, `bid`, `devId` |
| Удалить шлагбаум | `rmBarrier`, `bid`, `devId` |
| Заявка на модернизацию | `barrier_id`, `mailfrom`, `name`, `tel`, `address`, `mes` |

## Камеры и видео

### Ссылка на поток: список камер — проверено

| Поле | Значение |
|---|---|
| `cam` | `""` |
| `barrier_id` | необязательно: только камера этого шлагбаума |
| `login`, `key` | |

Ответ — **массив массивов** камер:

```json
[[{
  "id": "<hash>_<camId>",
  "camId": "<camId>",
  "token": "<TOKEN>",
  "domain": "cam0.privratnik.net",
  "session": "<SESSION>",
  "barrier_id": "<barrier_id>"
}]]
```

- `barrier_id` связывает камеру со шлагбаумом.
- Официальный клиент на экране шлагбаума берёт `data[0][0]`.
- С `barrier_id=…` ответ тот же, просто отфильтрован по шлагбауму.
- `token` постоянный: повторный запрос через несколько часов вернул тот же токен, и старый
  продолжал работать (проверено). Его можно кешировать.
- Что даёт поле `session`, не выяснено.

### Потоки Flussonic — проверено

База: `https://{domain}/{id}`. Ко всем адресам добавляется `?token={token}`.

| Путь | Что отдаёт | Кто использует |
|---|---|---|
| `/index.m3u8` | HLS | PrivratnikX (встроенный плеер Android) |
| `/index.ll.m3u8` | Low-Latency HLS | официальный клиент на iOS |
| `/mpegts` | непрерывный MPEG-TS по HTTP | официальный клиент на Android (ExoPlayer) |
| `/preview.mp4` | короткий ролик-превью, ~18 КБ | превью в списке |
| `/timeshift_rel-{N}.m3u8` | HLS из архива, N секунд назад от «сейчас» | перемотка назад |
| `/recording_status.json` | границы архива: `{"<id>": {"from": <unix>, "to": <unix>}}` | |

Параметры потока, которые видно в `index.m3u8`: H.264 Main (`avc1.4d001f`), 1280×720,
6 кадров/с, 50–70 кбит/с, без звука.

- Сегменты HLS длиной ~8,3 с (`EXT-X-TARGETDURATION:9`).
- Замер задержки на эмуляторе Android по часам в кадре камеры (часы камеры точные, см. снимок):

  | Способ | Задержка | До первого кадра |
  |---|---|---|
  | `index.m3u8` во встроенном плеере (`MediaPlayer`/`VideoView`) | ~43 с | несколько секунд |
  | `mpegts` во встроенном плеере | ~34 с | ~34 с |
  | Снимок через API (см. ниже) | 1–2 с | ~1 с |

  Встроенный плеер долго буферизует поток, и эта буферизация целиком уходит в задержку.
  Официальный клиент играет `mpegts` через ExoPlayer — там задержка, по всей видимости, меньше,
  но это не замерялось. PrivratnikX показывает снимок раз в секунду.
- Архив хранится примерно 5 суток (по `recording_status.json` — около 122 часов).
- Внутри `index.m3u8` лежит `tracks-v1/mono.ts.m3u8`, сегменты — `tracks-v1/ГГГГ/ММ/ДД/ЧЧ/ММ/СС-длительность.ts`.

Как официальный клиент выбирает адрес (`getBarrierStreamUrl(camera, offset, flag)`):

- Android, без флага, `offset < 5` → `/mpegts`;
- если `offset` ненулевой → `/timeshift_rel-{offset + 10}.m3u8`;
- иначе → `/index.ll.m3u8`.

### Снимок через API — проверено

```
GET https://api.privratnik.net:44590/app/api.php?login={login}&key={key}&preview&camId={camId}[&refresh={…}]
```

- `camId` — поле `camId` из ответа камер.
- Возвращает текущий кадр в JPEG 1280×720, ~80 КБ. Заголовок при этом `Content-Type: image/png`
  — он неверный.
- `refresh` необязателен.
- Кадр живой: часы в кадре отстают от момента запроса на 1–2 с, ответ приходит за ~1 с.

### Прочее

- `{сервер}/streamer/api/v3/streams` — API Flussonic. Отвечает `403 {"error":"authorization_failed"}`:
  нужен административный доступ к Flussonic.
- `https://apir2.privratnik.net/dvr/ranges` и `{база}/dvr/ranges` — сейчас 404.

## Остальные разделы — частично проверено

### Кошелёк

| Операция | Поля |
|---|---|
| Баланс | `finance=balance` — на тестовом аккаунте ответ `{"success":"false"}` |
| История операций | `finance=list`, `from`, `to` — без `from`/`to` ответ `{"success": true}` без данных |
| Пополнение | `finance=payment`, `sum` (не проверялось) |

### Разовые пропуска и парковки

| Операция | Поля |
|---|---|
| Настройки | `onetimepass=settings` — проверено, ответ ниже |
| Покупка вкл/выкл | `onetimepass=purchase`, `active` |
| Список пропусков | `onetimepass=list` |
| Список парковок | `onetimepass=parkinglist` |
| Создать пропуск | `onetimepass=add`, `parking_id`, `access_number`, `date_to`, `type`, `name`, `comment`, `plateNumber` |
| Удалить | `onetimepass=delete`, `id` |

Чтение (`settings`, `list`, `parkinglist`) проверено; изменяющие запросы не проверялись.
`list` и `parkinglist` на тестовом аккаунте возвращают `{"success": true}` без данных.

```json
{"success": true, "data": {"free": 10, "once_max_days": 1, "multi_max_days": 30, "paid": false, "price": 10}}
```
